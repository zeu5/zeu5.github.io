Making Strassen-Winograd work on GPUs

2026-07-17

The following post is an ode to The Morning Paper. From 2016, the blog was a constant source of learning for me, making complex research papers from a wide range of top computer science conferences accessible. As I stepped into the research world, I came to appreciate more the immense effort put into producing detailed reviews and explanations week after week. Below I write my first paper review in the hope of being as consistent and also discovering new areas of research. I will be presenting "Compiling Strassen-like Matrix Multiplication Algorithms to Fast CUDA Kernels" published in PLDI 2026

General Matrix Multiplication (GEMM) underpins most of the deep learning (Image recognition, Neural Nets, LLM inference and training) workloads. So it is very important to extract the peak performance from hardware designed specifically for these workloads. So it is all the more surprising that the best performing implementation of GEMM is not the one that provides the best asymptotic complexity. The paper makes a step in bridging this gap - efficiently implementing an algorithm that provides better asymptotic complexity.

Strassen's Algorithm Reloaded (SC '16) demonstrated the effectiveness of Strassen's algorithm (and variants) on CPUs. Motivated by this work, the paper under review extends the idea to GPUs. The key novelty comes from encoding the intermediate sub matrix multiplications in an IR, drawing out dependencies between the data of the sub matrix multiplications as a DAG, then picking a schedule that performs best. Let's unpack what each of that means. But first, why is it hard to implement an asymptotically faster algorithm?

Take the standard GEMM computation below. The standard cubic implementations allow for very sequential and predictable data streaming from memory to the core. As a result, the core (CPU or GPU) performing the computation is working (almost) all the time when memory is fetched in the background. Modern processors include prefetchers that fetch the data from memory to the core before it is needed based on prior access patterns. And as expected, they have evolved specifically to speed up such streamed accesses for very fast matrix multiplication.

However, with Strassen's algorithm, despite reducing the number of matrix multiplications required, it is non trivial to ensure a predictable streamed access such that the implementation is very fast. A naive implementation will simply not do.

The subcomputation involves 3 different operations, Input Sums, Sub MatMuls, Output Sums. The data access patterns for these operations are (1) not as predictable, and (2) requires repeated round-trips between the memory and the core. For both these reasons, it becomes difficult to implement the algorithm efficiently.

The paper proposes to fix it by ensuring that the data that is moved between the core and memory is reduced or appears to be streamed by keeping it in the registers (or fusing) and performing all necessary computation.
